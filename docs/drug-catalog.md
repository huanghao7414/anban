# 药品知识库

本机单用户药品目录与同时用药核查工具。使用 Python 3.10+ 标准库、SQLite 和浏览器原生界面。开发环境已验证 Python 3.14。业务服务仅监听本机地址，导入通过本地命令执行，网页和查询 API 只读。

## 启动

在项目目录执行以下命令。首次启动会从内置数据创建数据库。

```sh
python3 app.py serve
```

浏览器打开 [本机药品知识库](http://127.0.0.1:8765)。端口被占用时可指定 `serve --port 8766`。使用 Ctrl+C 停止服务。

## 试用核查

在目录中搜索“扑热息痛”，将华润三九（黄石）的小儿氨酚黄那敏颗粒和地奥集团成都药业的对乙酰氨基酚片加入同一清单，点击“核查用药”。结果会列出共同成分及两个产品的证据来源。点药名可查看成分、规格、生产企业、销售观察及原始记录。切换搜索条件保留当前清单，刷新页面清除清单。

也可在命令行复现：

```sh
python3 app.py check H42022510 H51021559 H32020797
```

第三个编号是苯巴比妥片。这张清单会返回一项成分重叠和一条待审核说明书线索。输入语义为同时使用的不同产品；重复输入同一产品或包含未知编号时，接口返回错误。剂量、人群禁忌、全类别相互作用和注射配伍不在当前覆盖范围。初始版本已审核相互作用规则为零，未命中不能用于推断联合用药安全。

## 更新与版本

`data/catalog.json` 是可编辑的完整初始数据包。复制此文件，修改顶层 `version`，保留应继续收录的数据，再执行：

```sh
python3 app.py import 新版目录.json
```

| 集合 | 建模约定 |
|---|---|
| sources | 给出资料标题、发布者、资料日期及原件 URL。产品、规则、渠道观察各自引用来源和原文位置 |
| ingredients | 以稳定 ID 标识成分，保存中文名和可搜索的别名 |
| products | 保存具体产品 ID、文号、企业、目录规格、途径、来源。成分项引用标准 ID，可填含量字符串。mapping 取 complete、partial 或 unknown |
| rules | 每条规则以一个具体产品及对方的成分、给药途径为适用范围。finding 保留依据的含义。初始状态 draft；药师复核后在新版本中设为 reviewed，填写 reviewer 和 reviewed_on。此版通过维护者录入审核信息，无账号或电子签名 |
| availability | 一条记录代表某个产品在某渠道、地区的一次确认。包含 product、channel、region、status（在售或停售）、observed_on、valid_until、source、locator。相同渠道地区取最近已发生的记录判断是否仍有效 |

导入会校验字段、引用关系、审核状态和日期，再生成不可覆写的 SQLite 版本文件，原子切换当前版本。重复导入相同文件可安全重试，同名但不同内容会被拒绝。导入失败保留原版本。页面刷新后进入新版本，已打开页面继续使用原版本；命令行可用 `check --version 2026-11-20.1` 重演旧结果。重新导入旧数据包可切回旧版本。备份 `.run/` 可保留所有已发布的数据库及活动版本指针。

## 接口与验证

| 方法和路径 | 参数或请求体 |
|---|---|
| GET /api/catalog | q、page、mapped=1。返回分页产品及本版本统计 |
| GET /api/product | id。返回产品档案和证据 |
| GET /api/rules | 列出当前版本规则与审核信息 |
| POST /api/check | JSON 对象，例如 `{"products":["H42022510","H51021559"]}` |

每个接口都可通过查询参数 version 选取历史版本。核查分别返回 duplicates、interactions、candidates、incomplete、missing_route 及版本号。成分重叠只说明成分相同，不推断过量。请求和用药清单不写入数据库。

